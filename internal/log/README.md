# 日志系统使用指南

## 📖 快速开始

日志系统已集成到项目中，无需额外配置即可使用。

## 🎯 使用方法

### 基础用法

```go
import "github.com/lwdjd/IPFAR/internal/log"

// Debug 级别 - 调试信息（最详细）
log.Debug("调试信息：%s", "详细信息")

// Info 级别 - 普通信息
log.Info("程序运行正常：%s", "参数")

// Warn 级别 - 警告信息
log.Warn("需要注意：%v", 问题)

// Error 级别 - 错误信息
log.Error("发生错误：%v", err)

// Fatal 级别 - 致命错误（会退出程序）
log.Fatal("无法恢复的错误：%v", err)
```

### 设置日志级别

在配置文件中设置 `log_level` 字段：

```json
{
  "language": "zh_CN",
  "log_level": "debug"
}
```

支持的级别：
- `debug` - 显示所有日志（开发推荐）
- `info` - 显示普通信息及以上（默认）
- `warn` - 只显示警告和错误
- `error` - 只显示错误

### 设置日志前缀

```go
log.SetPrefix("模块名")
// 输出：2026-04-13 11:00:00 [INFO] [模块名] 消息内容
```

## 📝 日志输出格式

```
时间戳 [级别] [前缀] 消息内容
```

示例：
```
2026-04-13 11:39:29 [INFO] [IPFAR] 配置文件加载成功
2026-04-13 11:39:29 [DEBUG] 从磁盘读取配置文件：config.json
2026-04-13 11:39:29 [ERROR] 读取磁盘配置文件失败：config.json, 错误：file not found
```

## 💡 最佳实践

1. **开发阶段**：使用 `debug` 级别，便于排查问题
2. **生产环境**：使用 `info` 或 `warn` 级别，减少日志量
3. **错误处理**：优先使用 `log.Error` 而不是 `fmt.Println`
4. **性能敏感**：避免在 `log.Debug` 中执行复杂操作
