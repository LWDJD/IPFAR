## 一、数据格式

1. Arweave上的文件采用：CID元数据(带Tags标签)->CAR文件(V2)。**CAR V2 必须带索引（Index），否则拒绝。** 元数据中包含可选的DAG引用项目(目的是可选的去重)。

## 二、验证策略

3. 主CAR文件大于100MB的文件无POW验证，采用被动验证。
4. 主CAR文件小于100MB的文件使用快速POW验证缓解，采用被动验证。
5. 开发全量验证功能，这适合重量级桥。

> **经济缓解**：同时配合存储费攻击缓解方案（见第六章）。小于100MB的文件依靠存储费+PoW缓解；大于100MB的文件依靠存储费缓解。

## 三、发现与获取

9. 从矿工获取原始数据，而是直接询问矿工，在块中搜索，采用去重随机游走的方式寻找数据，同时保证订阅或轮询最新的块。
11. 使用带导航的随机游走，使用bitlist存储块高是否存在IPFS数据即可，每一位表示一个块高度，0表示无，1表示有，采用某种不可信的分发方式，由于bitlist极小，所以可以轻易存储几十上百个不可信导航。

## 四、桥节点行为

2. Bitswap使用延迟回复机制降低自己被使用的优先级，减少arweave回源次数。
6. 开发本地文件缓存功能，这时候所有桥，可自定义缓存大小。
8. 可自定义网关接口，以便用户可以根据需要使用公共网关、本地网关、可验证网关路由等方式，最终安全性由IPFS兜底。
12. 需要同时原生数据和Bundle捆绑包中的数据。

## 五、去重与存储

7. 开发链上增量数据库，仅桥节点运营者自己使用，可以把已经验证过的数据写入桥上，未来可以直接调用此数据，无需二次验证。
10. 去重方法采用 无状态密码学排列（Feistel 网络 / 格式保留加密）。

## 六、安全与经济

垃圾数据攻击缓解方案：

- 小于100MB的文件依靠存储费+POW缓解；
- 大于100MB的文件依靠存储费缓解；
- 桥节点采用均态分布的方式收集数据，采用被动验证模式，仅在收到数据请求时验证数据是否合法；
- 采用尽力而为的DHT发布方式，每个文件都可能会被发布，降低冷数据无法访问的可能性；
- 采用完全发布的IPNI发布方式，收集到的数据立刻发布到IPNI（PASS 已验证，目前无法实现：IPNI 不是 Kubo 默认路由 — Kubo 默认走 DHT，要手动配 Routing.Type=custom 才能查 IPNI，生态兼容性差；Kubo 不跟 HTTP 302 重定向 — trustless gateway 客户端收到 302 直接判 HTTP Found: No，不走重定向）。
