# 日志系统使用指南

## 🎯 功能特性

### 核心功能
- ✅ **文件输出** - 自动记录到日志文件（带 UTF-8 BOM 编码）
- ✅ **控制台输出** - 可选择是否输出到终端
- ✅ **多种格式** - 支持文本格式和 JSON 格式
- ✅ **自动刷盘** - 定时将缓存写入磁盘（默认 5 秒）
- ✅ **线程安全** - 使用互斥锁保护并发访问
- ✅ **中文支持** - 完美支持 UTF-8 编码，中文不乱码

### 日志级别
- `DEBUG` - 调试信息（最详细）
- `INFO` - 普通信息（默认）
- `WARN` - 警告信息
- `ERROR` - 错误信息
- `FATAL` - 致命错误（会退出程序）

## 📖 使用方法

### 1. 配置文件设置

在 `config.json` 中配置：

```json
{
  "language": "zh_CN",
  "log_level": "info",
  "log_file": "logs/ipfar.log",
  "log_to_console": false,
  "log_format": "text"
}
```

**配置说明：**
- `log_level` - 日志级别：debug, info, warn, error
- `log_file` - 日志文件路径（可选，不填则只输出到控制台）
- `log_to_console` - 是否同时输出到控制台（默认 false）
- `log_format` - 日志格式：text（文本）或 json（JSON 格式）

### 2. 代码中使用

```go
package main

import (
    "github.com/lwdjd/IPFAR/internal/log"
)

func main() {
    // 确保程序退出时关闭日志
    defer log.Close()
    
    // 设置日志前缀
    log.SetPrefix("模块名")
    
    // 输出日志
    log.Debug("调试信息：%s", "详情")
    log.Info("普通信息")
    log.Warn("警告信息")
    log.Error("错误信息")
    // log.Fatal("致命错误") // 会退出程序
}
```

### 3. 动态修改配置

```go
// 修改日志级别
log.SetLevel(log.DEBUG)

// 修改前缀
log.SetPrefix("新模块")

// 动态设置日志文件
log.SetFile("logs/new.log")

// 禁用文件输出
log.DisableFile()

// 启用文件输出
log.EnableFile("logs/app.log")
```

## 📁 日志文件特性

### 编码格式
- 使用 **UTF-8 BOM** 编码
- Windows 终端可用 `Get-Content xxx.log -Encoding UTF8` 查看
- 推荐使用支持 UTF-8 的编辑器（如 VSCode、Notepad++）

### 文件格式

**文本格式示例：**
```
2026-04-13 16:18:16 [INFO] [IPFAR] 程序正常退出
2026-04-13 16:18:17 [ERROR] 发生错误：文件不存在
```

**JSON 格式示例：**
```json
{"timestamp":"2026-04-13 16:18:16","level":"INFO","prefix":"IPFAR","message":"程序正常退出"}
{"timestamp":"2026-04-13 16:18:17","level":"ERROR","message":"发生错误：文件不存在"}
```

### 性能优化
- 使用 `bufio.Writer` 缓冲写入
- 默认每 5 秒自动刷盘
- ERROR 和 FATAL 级别立即刷盘
- 避免频繁 I/O 操作

## 🔧 技术细节

### 初始化流程
1. `init()` 中初始化最小化日志（用于配置加载）
2. 读取配置文件
3. 根据配置重新初始化日志系统
4. `main()` 结束时调用 `log.Close()`

### 文件写入流程
1. 检查文件是否存在，不存在则创建
2. 如果是新文件，写入 UTF-8 BOM
3. 使用 `bufio.Writer` 缓冲写入
4. 定时刷盘或遇到 ERROR/FATAL 立即刷盘

### 并发安全
- 所有写操作都使用 `sync.Mutex` 保护
- 支持多个 goroutine 同时写日志
- 关闭操作也是线程安全的

## ⚠️ 注意事项

1. **必须调用 Close()** - 程序退出前确保调用 `log.Close()`，否则可能丢失日志
2. **文件权限** - 确保有权限创建日志文件和目录
3. **磁盘空间** - 定期清理旧日志文件
4. **敏感信息** - 避免在日志中记录密码、密钥等敏感信息
